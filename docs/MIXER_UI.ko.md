# 송출 오디오 믹서

## 현재 동작 (2026-10-24)

시작 경로 수정: 메인 상단에 `믹스 시작 / 믹스 중지` 버튼을 추가했습니다. 마이크는 선택 사항이며 처음에는 `마이크 사용 안 함`으로 시작하여 앱 소리만 송출할 수 있습니다. `송출 설정`에서 실제 마이크를 추가합니다. 시작 실패 시 메인 상태줄에 가상 장치 상태를 표시하며, 앱 카드는 `송출 시작 전 / 프로그램 연결 중 / 프로그램 캡처 중 / 프로그램 캡처 오류`로 구분합니다. 마이크가 없는 경우 캡처 API를 호출하지 않습니다.

실제 PC에서 Pack45의 `CABLE Input`과 `CABLE In 16ch`가 동시에 활성화되어 기존 코드가 출력 endpoint를 중복으로 판단하고 빈 ID를 반환하던 시작 차단을 재현했습니다. 두 endpoint 모두 공유 포맷이 stereo일 수 있어 채널 수만으로도 구분되지 않았습니다. 제조사 서비스·하드웨어 ID와 어댑터 소속 검증을 유지하고, native topology connector ID 순서로 표준 pin을 선택하도록 수정했습니다. 동일 connector의 모호한 중복은 차단합니다. 두 endpoint의 열거 순서가 바뀌어도 표준 endpoint를 선택하는 회귀 테스트를 추가했습니다. `process_capture_tests --virtual-output`에서 실제 가상 마이크 송출 엔진을 마이크 없이 시작하는 검증을 통과했습니다. 이 검증은 무음으로 실행하여 사용자 음성을 송출하지 않습니다.

믹서의 앱별 볼륨과 음소거는 송출 신호만 변경합니다. Windows 세션의 `SetMasterVolume`이나 `SetMute`는 호출하지 않습니다. `앱 추가`에서 고른 앱들의 오디오를 프로세스 루프백으로 개별 캡처하고, 앱별 게인을 적용한 뒤 마이크와 합산합니다. 믹스 출력 마스터를 적용한 동일 블록을 VB-CABLE, 선택적 WAV 저장, 스피커 듣기로 보냅니다.

`송출 설정`에서 마이크를 고르고 믹스를 시작합니다. 메인 화면의 `믹스 듣기`를 켜면 최종 믹스가 Windows 기본 스피커/헤드폰에도 재생됩니다. 출력 장치를 다시 캡처하거나 CABLE을 수동 선택하지 않습니다. 듣기만 꺼도 가상 마이크 송출과 WAV 저장은 계속됩니다. 기본 출력이 송출용 가상 endpoint와 같으면 재생을 차단합니다. 기본 출력 장치 변경 후에는 듣기를 껐다 켭니다. 스피커 연결 실패는 송출을 중단하지 않습니다.

앱 추가·제거는 송출 중에도 반영되며, 같은 실행 파일의 여러 PID는 한 입력으로 묶습니다. 같은 앱의 부모·자식 PID가 함께 나열되면 중복 프로세스 트리 캡처를 피합니다. 입력의 종료·실패는 다른 앱이나 마이크 송출을 멈추지 않습니다. 종료한 앱은 대기 상태로 남고 같은 경로로 다시 실행하면 재연결합니다. 슬라이더와 음소거는 대기·새로고침·재연결 중에도 유지합니다. 목록 갱신은 약 2초 간격이고 오디오 워커는 약 250ms 간격으로 입력 변경을 반영합니다.

프로세스 활성화는 입력별 작업 스레드에서 수행하여 다른 입력 처리를 막지 않습니다. 최종 샘플 합산 후 한 번 제한하며, 앱별 게인과 음소거는 10ms 블록 동안 부드럽게 적용합니다. 스피커 재생은 별도 스레드와 최대 4블록 큐를 사용합니다. 큐가 밀리면 오래된 블록을 버려 최신 믹스를 유지합니다. UI 크기는 640×654 논리 픽셀입니다.

검증: Release 빌드와 CTest 5개 통과. 모의 Windows 세션에 대한 볼륨·음소거 쓰기 호출 0건, 두 앱의 독립 감쇠·음소거·최종 합산, 선택 목록 상태 유지와 출력 마스터를 검사했습니다. `process_capture_tests`는 실제 프로세스의 저음량 테스트 신호를 캡처하고, 송출용 음소거 후 원래 Windows 세션 설정이 유지됨을 확인했습니다. `mix_monitor_tests --hardware-smoke`는 기본 스피커로 실제 PCM 블록 재생, 켜기·끄기·재시작, 동일 가상 endpoint 차단과 종료를 검사합니다. 프로세스 활성화 콜백은 IAgileObject와 free-threaded marshaler를 제공하도록 수정했으며, 실제 활성화 성공을 확인했습니다. [Microsoft API 문서](https://learn.microsoft.com/windows/win32/api/mmdeviceapi/nf-mmdeviceapi-activateaudiointerfaceasync).

최종 GUI 배치, 여러 앱의 장시간 동시 송출, 장치 분리·다중 DPI, VB-CABLE/Discord 수신 및 음질 청취는 미검증입니다. 원래 앱 재생음과 스피커 듣기가 같은 스피커에서 겹칠 수 있으며, 마이크 사용 시에는 헤드폰을 권장합니다.

## 이전 UI 개발 기록

아래는 이전 배포 스냅샷의 기록입니다. 현재 동작은 위 설명을 따릅니다.
## 믹스 출력 마스터

최신 `PortableMixer-MixOutput.exe`에는 `믹스 출력`을 기본 채널로 표시합니다. 모든 페이지의 오른쪽 끝을 믹스 출력용으로 고정하고, 왼쪽 세 칸에 추가한 앱을 배치합니다. 앱이 더 많으면 앱 목록만 페이지로 전환합니다. 믹스 출력에는 제거 버튼이 없습니다.

슬라이더와 음소거는 오디오 엔진의 최종 믹스 신호에 적용합니다. 합산 후 처리한 동일 블록이 가상 마이크 송출과 선택적 WAV 기록으로 전달됩니다. 음소거와 볼륨 변경은 10ms 동안 부드럽게 적용하며, 음소거 상태로 송출을 시작하면 첫 블록부터 무음입니다. 미터는 최종 볼륨을 적용한 믹스 신호의 피크를 읽고, 송출이 멈추면 0을 표시합니다. 정지 상태에서도 다음 송출에 사용할 볼륨/음소거를 설정할 수 있습니다. 이 채널에서 Windows 기본 출력 장치의 볼륨을 제어하던 경로는 제거했습니다.

검증: Release 빌드와 테스트 4개 통과. 믹스 출력의 스테레오 감쇠, 출력 피크, 음소거/해제 램프, 음소거 중 볼륨 변경 및 음소거 상태로 시작 시의 무음 유지를 검사했습니다. UI 제어 상태와 오디오 엔진이 공유하는 출력 상태의 연결 및 정지 시 미터도 테스트했습니다. 이번 변경의 실제 장치 송출 청취는 수행하지 않았습니다. Computer Use의 앱 실행 승인이 시간 초과되어 최종 UI 실행 캡처도 수행하지 못했습니다.

## 직접 추가한 프로그램만 표시

최신 빌드: `downloads/PortableMixer-MixOutput.exe`. 시작 시 앱 선택 목록은 비어 있고, 기본 믹스 출력과 `앱 추가`에서 고른 프로그램만 표시합니다. 선택은 현재 실행 중에 유지합니다. 앱 카드의 `×`는 믹서 표시만 제거하며 앱을 종료하거나 볼륨을 바꾸지 않습니다.

같은 실행 파일 경로의 여러 PID/장치 오디오 세션은 카드 하나로 묶어 볼륨과 음소거를 함께 적용합니다. 같은 파일 이름이라도 실행 경로가 다르면 별도 앱입니다. 추가 목록에는 `이미 믹서에 추가됨`을 표시하고 추가 버튼 및 더블클릭 중복 추가를 차단합니다. 종료된 앱은 대기 카드로 유지하며, 같은 실행 파일을 다시 실행하면 연결합니다.

추가 순서대로 한 페이지 최대 3개 앱과 오른쪽 끝의 믹스 출력을 간격을 두고 배치합니다. 나머지 앱은 이전/다음 페이지로 이동합니다. 사용하지 않는 앱 카드와 자동 발견한 미선택 앱은 표시하지 않습니다.

검증: Release 빌드 및 코어/선택 목록/가상 장치/번들 테스트 4개 통과. 선택 목록 테스트에서 초기 미선택, 경로별 중복 방지, 여러 세션 병합, 다른 앱의 볼륨 유지, 종료·재실행 및 제거를 확인했습니다. 실제 UI에서는 빈 시작 화면, Chrome/Steam 추가, 이미 추가됨 표시, 두 카드의 간격 및 제거 후 재정렬을 확인했습니다. UI만 여는 일반 권한 검증 프로그램을 사용했으며, 실제 장치 설치나 송출을 시작하지 않았습니다.

## 내부 창과 실제 앱 아이콘

`downloads/PortableMixer-Polished.exe`는 프로그램 추가·방송 설정 팝업과 녹음 설정 화면에 다크 테마를 적용한 빌드입니다. 팝업은 메인 창 가운데에 표시되고 화면 작업 영역을 벗어나지 않도록 배치합니다. 프로그램 추가 목록은 실행 파일 아이콘, 전체 실행 파일 이름, 세션 상태, PID를 함께 표시합니다. 믹서의 첫 글자 표기도 실제 실행 파일 아이콘으로 교체했습니다. 아이콘을 읽을 수 없는 프로세스는 Windows 기본 앱 아이콘을 표시하며, 시스템 소리는 Windows 오디오 파일 아이콘을 사용합니다.

아이콘은 실행 파일 경로 기준으로 캐시하고 공유 소유권으로 수명을 관리합니다. 새로고침 때 PID 재사용으로 이전 앱의 아이콘이 남지 않도록 경로를 다시 확인합니다. 아이콘 캐시는 최대 64개 경로를 보관합니다.

Release 빌드 및 코어 테스트를 통과했습니다. 실제 GUI에서 Chrome/Steam 아이콘, 추가창 목록 및 더블클릭 선택, 방송 설정 취소/빈 입력 검증, 녹음 화면 컨트롤을 확인했습니다. 별도 작업의 관리자 권한 매니페스트는 유지했습니다. 자동 UI 조작은 동일 오브젝트에 일반 권한 매니페스트만 적용한 검증용 빌드로 진행했으며, 가상 마이크 설치·송출은 이번 UI 검증 범위가 아닙니다. Windows 기본 파일 열기/저장 대화상자는 운영체제의 스타일을 따릅니다.

## 컴팩트 디자인

기본 믹서 화면을 800×846에서 640×530 논리 픽셀로 축소했습니다(Windows 배율에 따라 실제 픽셀 크기는 달라집니다). 어두운 배경, 앱별 포인트 색상, 직접 그리는 세로 슬라이더와 둥근 버튼을 사용합니다. 기본 화면에서는 PID와 긴 설명을 제외했습니다. 녹음 설정 화면으로 전환할 때는 기존 설정 크기로 확장하고, 믹서로 돌아오면 다시 작아집니다.

배포 파일: `downloads/PortableMixer-Compact.exe`. 실제 Windows 화면에서 배치, 슬라이더 드래그, 설정 화면 전환과 크기 복귀를 확인했습니다. 테스트 중 변경한 Steam 볼륨은 100%로 복구했습니다. Release 빌드 및 기존 코어 테스트가 통과했습니다.

첫 화면은 사용자가 추가한 앱을 나란히 표시하는 볼륨 믹서입니다. 추가 팝업은 Windows 오디오 세션이 있는 프로그램을 보여줍니다. 재생 중인 앱은 레벨 미터가 표시되며, 선택한 앱이 종료되면 대기 상태로 유지합니다.

- 추가한 앱별 세로 슬라이더: 위쪽 100%, 아래쪽 0%.
- 앱별 음소거/해제. Windows 세션 볼륨에 즉시 적용되며, 앱을 종료해도 Windows 볼륨 설정은 유지됩니다.
- 같은 실행 파일의 여러 PID와 출력 장치 세션을 하나의 채널로 묶습니다.
- 앱 3개와 믹스 출력을 표시하며 이전/다음 버튼으로 앱 페이지를 이동합니다. 세션 목록은 약 2초마다 갱신됩니다.
- `프로그램 추가` 팝업에서 선택하면 믹서에 새 카드를 추가하고 해당 페이지로 이동합니다. 앱이 없으면 먼저 소리를 재생합니다.
- `녹음 / 입력 설정`으로 가상 마이크 송출 및 선택적 WAV 저장 설정 화면을 엽니다. 녹음 입력은 여전히 프로그램 1개와 마이크입니다. 첫 화면의 여러 앱 볼륨 제어와 여러 프로그램 동시 녹음은 별개입니다.
- `MP4 방송 설정`은 파일/서버/키 설정 창이며, 영상 방송 송출 엔진은 아직 연결되지 않았습니다.

## 검증 (2026-10-24)

- `build/volume-mixer` Windows x64 Release 빌드 및 기존 코어 테스트 1개 통과.
- 실제 Windows GUI를 실행하여 Chrome, Steam, 출력 장치별 시스템 소리 4개 채널 및 Chrome 레벨 미터 확인.
- Steam 세로 슬라이더를 100%에서 50%로 변경한 후 별도 읽기 전용 COM 프로세스로 Windows 세션 값 0.5 확인. 다른 앱/장치 값은 유지됨.
- Steam 음소거 후 별도 프로세스로 muted=1 확인. 검사 후 100%, muted=0으로 복구 확인.
- 프로그램 선택 팝업의 Chrome/Steam 목록, Chrome 선택 적용, 녹음 화면 전환 및 믹서 복귀 확인.
- 여러 DPI 및 장치 분리/재연결, 5개 이상 채널의 페이지 이동은 수동 실기 검증 미수행.

배포 파일: `downloads/PortableMixer-VolumeMixer.exe`. 첫 화면 제목은 `Portable Mixer — 프로그램 볼륨 믹서`입니다. 기존에 실행 중인 구버전 창은 자동 교체되지 않습니다.

사용 API: [ISimpleAudioVolume::SetMasterVolume](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-isimpleaudiovolume-setmastervolume).
