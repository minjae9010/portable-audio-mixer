# VB-CABLE 장치 수명 검증

## 단일 EXE 설치 패키지 (0.5)

`cmake/EmbedCable.cmake`가 원본 Pack45 ZIP의 고정 SHA256을 확인하고 모든 파일을 RCDATA로 포함합니다. 앱이 미설치 상태를 감지하면 제조사/Donationware 고지와 설치 동의를 표시합니다. 동의하면 임의 이름의 관리자/SYSTEM 전용 임시 폴더에 파일을 풀고 공식 EXE의 Authenticode 신뢰를 검사한 다음 설치 창을 엽니다. 실행 중 패키지 파일에 쓰기/삭제 공유를 허용하지 않습니다. 설치 창 종료 후 표준 VB-CABLE을 즉시 비활성화하고 PnP 문제 코드 22(CM_PROB_DISABLED)를 확인한 뒤 결과를 안내합니다. 늦은 PnP 열거를 위해 최대 20회, 500ms 간격으로 재시도합니다. 설치 취소/미감지, 여러 장치, 비활성화 실패는 성공으로 표시하지 않습니다. 설치부터 비활성화 확인까지 런타임 감시와 동일한 전역 뮤텍스를 보유해 다른 인스턴스와 충돌하지 않습니다. 이후 추출한 파일을 정리하고 앱을 종료합니다. 재부팅 후에만 장치가 생기는 경우에는 즉시 비활성화를 확인할 수 없음을 안내합니다. 신뢰 확인은 로컬 인증서 저장소와 캐시를 사용하므로 온라인 폐기 여부를 추가 조회하지 않습니다.

설치 성공을 단순 프로세스 종료 코드로 단정하지 않습니다. 원본 설치 UI에서 사용자가 진행/취소하며, 이후 앱 실행에서 장치를 다시 검색합니다. 빌드와 내장 파일 31개 원본 해시 검증은 완료했지만 실제 설치 UI 실행과 드라이버 설치는 미수행입니다. 원본 ZIP은 재현 빌드에 필요하며 배포 사용자에게는 EXE만 제공합니다.

## 구현

`src/virtual_microphone.hpp`는 VB-CABLE Pack45 INF의 하드웨어 ID `VBAudioVACWDM`과 서비스 `VBAudioVACMME`가 모두 일치하는 PnP 장치 한 개만 찾습니다. 장치 표시 이름은 선택 기준으로 사용하지 않습니다. 두 개 이상이면 임의 선택하지 않습니다.

같은 EXE의 `--cable-guard` 내부 모드가 장치 활성화와 비활성화를 소유합니다. 부모 프로세스 핸들, 종료 이벤트, 준비 이벤트, 공유 메모리 핸들만 `PROC_THREAD_ATTRIBUTE_HANDLE_LIST`로 상속합니다. PID 재사용으로 다른 프로세스를 감시하지 않습니다. 전역 이름 뮤텍스로 두 인스턴스가 동시에 같은 장치를 관리하지 못하게 합니다.

부모 프로세스 종료 또는 정상 종료 이벤트가 발생하면 `CM_Disable_DevNode(CM_DISABLE_UI_NOT_OK | CM_DISABLE_PERSIST)`를 호출합니다. 실패 시 최대 5회 시도하고 오류를 알립니다. 다음 실행에서는 `CM_Enable_DevNode`를 사용합니다. 프로그램 강제 종료는 감시 프로세스가 살아 있는 경우에 처리됩니다. 전원 차단 및 두 프로세스 동시 종료는 보장할 수 없습니다.

오디오 엔드포인트는 PnP 조상 또는 DeviceTopology의 연결된 어댑터 식별자로 연결합니다. 오디오 엔진도 선택한 출력이 관리 대상 VB-CABLE에 속하는지 다시 검증합니다. 기본 출력으로의 자동 대체는 하지 않습니다. 관리 중인 캡처 엔드포인트는 믹서 입력에서 제외합니다.

WASAPI shared-mode 변환을 사용해 48 kHz/stereo PCM16을 렌더링합니다. 렌더 큐가 가득 차면 해당 10 ms 블록을 버리고 진단 overflow 카운터에 프레임 수를 더합니다. 시간 제한 없는 출력 쓰기나 무한 큐를 사용하지 않습니다. 장시간 클럭 드리프트/지연 실기 검증이 필요합니다.

## 자동 검증

- 앱 LLVM-MinGW Release 빌드: 통과.
- 기존 코어 테스트: 통과.
- `virtual_device_tests`: 9개 장치 수명 시나리오 통과. 실제 Windows 이벤트/뮤텍스/공유 메모리와 모의 장치 변경 함수를 사용합니다. 실제 드라이버나 장치를 바꾸지 않습니다.
- 공식 Pack45 ZIP SHA256: `b950e39f01af1d04ea623c8f6d8eb9b6ea5c477c637295fabf20631c85116bfb`.
- 공식 설치 EXE 및 Windows 10/11 x64 CAT의 Authenticode 유효성을 확인했습니다. CAT 발급 대상은 Microsoft Windows Hardware Compatibility Publisher입니다.

## 실기 검증 절차 (아직 미수행)

1. 공식 Pack45 설치 및 재부팅 후 표준 VB-CABLE 한 개가 있는지 확인합니다.
2. 앱 실행 시 Windows 캡처와 재생 엔드포인트가 활성화되는지 확인합니다.
3. 앱 실행 후 Discord 입력을 CABLE Output으로 선택하고 테스트 오디오를 믹싱해 수신을 확인합니다. 타인에게 전송하지 않는 마이크 테스트를 사용합니다.
4. 송출 중지 시 스트림이 멈추고 장치는 유지되는지 확인합니다.
5. 창 X로 종료 후 VB-CABLE PnP 문제 코드가 비활성(22) 상태인지, Discord 오디오가 끊겼는지 확인합니다. Windows 비활성 장치 목록에는 남을 수 있습니다.
6. 다시 실행하여 활성화되는지 확인합니다.
7. **주 앱 프로세스만** 강제 종료하고 감시 프로세스가 장치를 비활성화한 후 종료되는지 확인합니다.
8. 두 앱을 실행해 두 번째 앱이 장치를 제어하지 않는지 확인합니다.
9. 최소화/트레이 숨김, 로그오프, 정상 재부팅, 렌더 장치 연결 끊김, 장시간 송출을 확인합니다.
10. 실제 마이크/스피커와 Steam/NVIDIA 가상 장치 상태가 바뀌지 않았는지 확인합니다.

실기 확인 전에는 장치 목록 제거 시간이나 Discord의 재선택 필요 여부를 확정할 수 없습니다. 보안 설정 변경과 자체 드라이버 설치는 필요하지 않습니다.
